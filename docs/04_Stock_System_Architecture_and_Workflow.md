# Stock System Architecture & Workflow (CostFlow)

เอกสารนี้สรุปแนวคิดและสถาปัตยกรรมระบบคลังสินค้า (Stock System) เพื่อแก้ปัญหาความไม่สอดคล้องกันระหว่าง **"ข้อมูลการสั่งซื้อ (PO/WO)"** กับ **"ข้อมูลหน้างาน (Physical Bins)"** โดยประยุกต์ใช้เทคนิค Fuzzy Matching เป็นตัวช่วยเชื่อมโยง (Cross-Reference)

---

## 1. โครงสร้างฐานข้อมูล (Data Domains)
ระบบแบ่งออกเป็น 3 ส่วนหลัก (แต่ทำงานอยู่บน Database เดียวกัน):

### 🗄️ ก้อนที่ 1: ฝั่งจัดซื้อและรับของ (Purchasing / Inbound)
*   **ตาราง:** `SavedOrderBatches`, `SavedOrderItems`
*   **หน้าที่:** เก็บข้อมูลว่าสั่งอะไรเข้ามา ราคาเท่าไหร่ (อิงชื่อยาวๆ และรหัสตามใบสั่งซื้อ/ใบ WO)
*   **บริบท:** เป็นข้อมูลที่รับเข้ามาจากภายนอก ชื่อมักจะไม่ตรงกับป้ายหน้างาน

### 🗄️ ก้อนที่ 2: ฝั่งจัดการสต๊อกหน้างาน (Master Stock / Bins)
*   **ตาราง:** `StockItems` (หรือ `MasterProducts`)
*   **หน้าที่:** เป็นตัวแทนของ **"ตะกร้าหรือป้ายชื่อ"** ที่มีอยู่จริงในโกดัง (เช่น ป้ายชื่อ `น็อต M6`) เก็บเฉพาะยอดคงเหลือปัจจุบัน
*   **บริบท:** หน้างานจะอ้างอิงและทำธุรกรรมผ่าน "ชื่อตะกร้า" เหล่านี้เท่านั้น

### 🗄️ ก้อนที่ 3: สะพานเชื่อมและประวัติ (Mapping & Transactions)
*   **ตาราง:** `ItemMappings` (พจนานุกรมคำพ้อง) และ `StockLogs` (ประวัติเข้า-ออก)
*   **หน้าที่:** 
    *   `ItemMappings`: จำว่าของจากก้อน 1 (ชื่อยาวๆ) ต้องไปหย่อนลงตะกร้าไหนในก้อน 2
    *   `StockLogs`: บันทึกประวัติว่าใครเบิกอะไรจากตะกร้าไหนไปเมื่อไหร่

---

## 2. ขั้นตอนการนำระบบขึ้นใช้งานจริง (Go-Live Strategy)

เนื่องจากระบบเดิมหน้างานใช้ Google Sheets ในการบันทึก การเริ่มใช้ CostFlow ห้ามเริ่มต้นสต๊อกที่ 0 เด็ดขาด ต้องมี **ยอดยกมา (Opening Balance)** เสมอ

*   **Step 1:** Export ข้อมูลสต๊อกหน้างานล่าสุดจาก Google Sheets (รายชื่อสินค้า + ยอดคงเหลือ)
*   **Step 2:** นำข้อมูลนั้นมา **Import** ลงตาราง `StockItems` (ก้อนที่ 2)
*   **Step 3:** ชื่อสินค้าที่ Import เข้ามานี้ จะกลายเป็น **Primary Key (รหัสอ้างอิงตะกร้า)** สำหรับระบบทั้งหมด

---

## 3. Workflow การรับของเข้าและการทำงานของ Matching Engine

จุดเด่นของระบบนี้คือ **"เราไม่สนใจรหัส WO เวลาจัดเก็บ แต่เราดูจากชื่อตะกร้าเป็นหลัก"** โดยใช้ NLP/Fuzzy Matching มาทำงานเฉพาะตอนรับของเท่านั้น

1.  **รับของเข้า (Receive):** จัดซื้อคีย์รับของผ่านระบบ (เช่น ชื่อ `สกรูน็อตหัวหกเหลี่ยมชุบดำ M6 x 20mm`)
2.  **ด่านคัดกรองตัวเลข (Number Isolation):** 
    *   ระบบจะดึงตัวเลขและหน่วยออกมาแยกไว้ต่างหาก (ป้องกันปัญหาเช่น `29 นิ้ว` vs `129 นิ้ว`)
    *   ถ้าวัดตัวเลขแล้วไม่ตรงกัน ระบบจะแจ้งเตือนและไม่อนุญาตให้ Auto-Match เด็ดขาด
3.  **หาตะกร้า (Fuzzy Matching):** 
    *   ระบบรัน Fuzzy Match นำชื่อที่รับเข้ามา เทียบกับชื่อตะกร้าทั้งหมดใน `StockItems`
    *   ระบบเด้งถาม Admin: *"คุณต้องการนำของชิ้นนี้ เก็บเข้าตะกร้าสต๊อกชื่อ **'น็อต M6'** ใช่หรือไม่? (Confidence 85%)"*
4.  **จำความสัมพันธ์ (Alias Memory):** 
    *   เมื่อ Admin กดยืนยัน ของจะถูกบวกเข้าตะกร้า `น็อต M6` ทันที
    *   ระบบบันทึกลงตาราง `ItemMappings` ว่า `สกรูน็อตหัวหกเหลี่ยมชุบดำ M6 x 20mm = น็อต M6`
5.  **ความฉลาดในอนาคต:** 
    *   ครั้งต่อไปที่มีการรับของชื่อเดิมเข้ามา ระบบจะเจอใน `ItemMappings` ทันที และเอาของหย่อนลงตะกร้า `น็อต M6` ให้อัตโนมัติ 100% โดยไม่ต้องรัน Fuzzy Matching หรือถาม Admin อีก
6.  **หน้างานทำงานปกติ:** 
    *   ฝ่ายผลิตเวลาเบิกของ ก็จะเห็นแค่ชื่อ `น็อต M6` เหมือนเดิม ทำให้ทำงานได้ราบรื่น ไม่ต้องเรียนรู้รหัสใบสั่งซื้อ

---
