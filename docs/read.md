# สรุป Flow การทำงานของระบบ CostFlow

## ภาพรวมระบบ
ระบบ CostFlow เป็นระบบจัดการและติดตามคำสั่งผลิตชิ้นส่วน (Production Order Tracking) ที่ช่วยในการ:
- จัดการและติดตามใบสั่งผลิต (Work Order - WO)
- เปรียบเทียบแผนการผลิตกับไฟล์สั่งผลิตจริง
- คำนวณค่าใช้จ่ายประจำเดือน
- จัดการข้อมูลอ้างอิงราคาสินค้า

---

## โครงสร้างระบบ

### ฐานข้อมูลหลัก
1. **Report** - เก็บข้อมูลไฟล์รายงานสั่งผลิตหลัก
2. **OrderTrackingMaster** - รายการ PO (Purchase Order) จากไฟล์สั่งผลิต
3. **WeeklyPlan** - ไฟล์แผนผลิตรายสัปดาห์
4. **WeeklyPlanDetail** - รายละเอียด PO ในแผนผลิตแต่ละสัปดาห์
5. **MonthlyOrderAction** - บันทึกการรับมอบสินค้าประจำเดือน
6. **ProductPrice** - ข้อมูลอ้างอิงราคาสินค้า

### ผู้ใช้งาน
- **Admin** - สิทธิ์เต็ม สามารถนำเข้าไฟล์ จัดการค่าใช้จ่าย และดูรายงานทั้งหมด
- **Staff** - ค้นหาราคาสินค้าอ้างอิงเท่านั้น

---

## Flow การทำงานหลัก

### 1. นำเข้าไฟล์สั่งผลิต (File Import)
**หน้า:** `/FileImport/Index`

#### ขั้นตอน:
1. **อัปโหลดไฟล์สั่งผลิตหลัก** (ไฟล์ Excel .xlsx หรือ CSV)
   - รองรับไฟล์สูงสุด 25 MB
   - ระบบจะตรวจสอบว่าไฟล์ไม่เสียหาย ไม่มีรหัสผ่าน และมีข้อมูล
   
2. **อ่านข้อมูลจากไฟล์**
   - ระบบจะอ่านทุก Sheet ในไฟล์
   - แยกข้อมูลทีละแถว พร้อมชื่อ Column
   - สร้าง `sessionId` สำหรับเก็บข้อมูลชั่วคราวในหน่วยความจำ

3. **แสดงตัวอย่างข้อมูล**
   - ผู้ใช้เลือก Sheet ที่ต้องการ
   - ระบบแสดงตัวอย่าง 10 แถวแรก
   - ระบบแสดงรายชื่อ Column ทั้งหมด

#### ตัวอย่างข้อมูลในไฟล์สั่งผลิต:
```
ใบขออนุมัติ | วันที่ขออนุมัติ | วันที่อนุมัติ | มูลค่าสั่งผลิต | หมายเหตุ | เลขที่ใบสั่งผลิต
WO26060219  | 16/06/2026    | 18/06/2026   | 1026.52        | ตุ๊กตา...  | 26062506
```

---

### 2. จับคู่กับแผนผลิต (File Merge)
**หน้า:** `/FileMerge/Index`

#### ขั้นตอน:
1. **เลือกรายงานสั่งผลิตที่ต้องการจับคู่**
   - ดึงรายการ Reports ทั้งหมดจากฐานข้อมูล
   - แสดงชื่อรายงาน จำนวน PO และข้อมูลสรุป

2. **อัปโหลดไฟล์แผนผลิตรายสัปดาห์**
   - อัปโหลดไฟล์ Excel/CSV ที่ผู้ผลิตส่งมา
   - ไฟล์นี้จะมีรายละเอียด:
     - รหัส PO (เลขที่ใบสั่งผลิต)
     - ชื่องาน/ชิ้นส่วน
     - แผนก (Department)
     - สถานะงาน
     - **วันที่เป้าหมายส่งมอบ** (Delivery Target Date)
     - ราคา

3. **เลือก Column ที่ใช้จับคู่**
   - เลือก Column ที่เก็บเลขที่ PO
   - เลือก Column อื่นๆ เช่น แผนก, ชื่องาน, วันที่ส่งมอบ, ราคา

4. **ระบบทำการจับคู่อัตโนมัติ**
   - ดึง PO ทั้งหมดจาก Report ที่เลือก
   - เปรียบเทียบเลขที่ PO ในไฟล์แผนผลิตกับฐานข้อมูล
   - ถ้า PO ตรงกัน → จับคู่สำเร็จ (`IsMatched = true`)
   - บันทึกวันที่เป้าหมายส่งมอบและข้อมูลเพิ่มเติม

5. **บันทึกผลลัพธ์**
   - สร้าง `WeeklyPlan` (บันทึกไฟล์แผนผลิต)
   - สร้าง `WeeklyPlanDetail` (รายละเอียดแต่ละ PO)
   - อัปเดต Report: จำนวน PO ที่จับคู่ได้

#### ตัวอย่างการจับคู่:
```
ไฟล์สั่งผลิต:        แผนผลิตสัปดาห์:
WO26060219 ------->  26062506 (จับคู่สำเร็จ)
WO26060214 ------->  26062425 (จับคู่สำเร็จ)
WO26060213 ------->  ไม่มีในแผน (ไม่จับคู่)
```

---

### 3. ดูรายงานและข้อมูลที่จับคู่ (Report)
**หน้า:** `/Report/Index`

#### ขั้นตอน:
1. **แสดงรายการรายงานทั้งหมด**
   - กรองตามปี (Year Filter)
   - แสดงชื่อรายงาน, จำนวน PO, PO ที่จับคู่ได้, วันที่สร้าง

2. **ดูรายละเอียดรายงาน** (`/Report/Details`)
   - แสดง PO ทั้งหมดในรายงาน
   - แสดงว่า PO ไหนจับคู่กับแผนผลิตแล้ว
   - แสดงวันที่เป้าหมายส่งมอบ (Delivery Target)

3. **ดูแผนผลิตรายสัปดาห์ที่อัปโหลด**
   - แสดงรายการไฟล์แผนผลิตทั้งหมดที่จับคู่กับรายงานนี้
   - คลิกดูรายละเอียดแต่ละไฟล์

4. **Export ข้อมูลเป็น Excel**
   - ส่งออกรายงานเป็นไฟล์ Excel
   - ใส่ชื่อไฟล์กำหนดเองได้

---

### 4. คำนวณค่าใช้จ่ายประจำเดือน (Monthly Cost)
**หน้า:** `/MonthlyCost/Index`

#### ขั้นตอน:
1. **แสดงรายการเดือนทั้งหมด**
   - ระบบจะสกัดเดือน/ปีจากวันที่เป้าหมายส่งมอบของทุก PO
   - แสดงเป็นรายการเดือน เช่น "มิถุนายน 2569", "กรกฎาคม 2569"
   - แสดงจำนวน PO ที่ครบกำหนดในเดือนนั้นๆ

2. **เข้าไปดูรายละเอียดเดือน** (`/MonthlyCost/Detail`)
   - แสดง PO ทั้งหมดที่มีวันที่เป้าหมายส่งมอบในเดือนนั้น
   - แสดงสถานะการรับมอบ:
     - **Pending** = ยังไม่ระบุ
     - **Received** = รับมอบแล้ว → นับเข้าค่าใช้จ่ายเดือนนี้
     - **Deferred** = ผ่อนไปเดือนถัดไป
     - **Skipped** = ข้าม (ไม่นับค่าใช้จ่าย)

3. **จัดการการรับมอบสินค้า**
   - ผู้ใช้สามารถเลือกสถานะแต่ละ PO:
     - ✅ **รับแล้ว** → บันทึก Action = "Received"
     - ⏭️ **ผ่อนไปเดือนหน้า** → บันทึก Action = "Deferred"
     - ❌ **ข้าม** → บันทึก Action = "Skipped"

4. **บันทึกลงฐานข้อมูล**
   - บันทึกลง `MonthlyOrderAction`
   - เก็บข้อมูล:
     - `OrderTrackingMasterId` - PO ไหน
     - `MonthYear` - เดือน/ปี เช่น "2026-07"
     - `Action` - สถานะ (Received/Deferred/Skipped)
     - `ActionPrice` - มูลค่าที่ใช้คำนวณ
     - `DeferredFromMonth` - ถ้าผ่อนมาจากเดือนก่อน
     - `IsForcedPayment` - บังคับจ่ายจากการผ่อน

5. **คำนวณสรุปค่าใช้จ่ายเดือน**
   - รวม PO ที่สถานะ = "Received"
   - รวม PO ที่ผ่อนมาจากเดือนก่อน (`IsForcedPayment = true`)
   - แสดงยอดรวมค่าใช้จ่ายเดือนนั้น

---

### 5. การจัดการไฟล์ซ้ำในเดือนเดียวกัน

#### คำถาม: ถ้าสั่งผลิตเพิ่มในเดือนเดียวกัน ระบบจะจัดการอย่างไร?

**ตัวอย่าง:**
```
วันที่ 5 มิ.ย.: อัปโหลด WO26060219, WO26060214, WO26060213
วันที่ 10 มิ.ย.: อัปโหลด WO26060167, WO26060166 (เดือนเดียวกัน)
วันที่ 25 มิ.ย.: อัปโหลด WO26060156, WO26060154 (เดือนเดียวกันอีก)
```

#### วิธีจัดการ:
1. **ระบบเช็คจากรหัส PO**
   - ก่อนบันทึก `OrderTrackingMaster` ใหม่
   - ระบบเช็คว่ามี `PoNumber` นี้อยู่แล้วหรือไม่
   - **ถ้าซ้ำ → ข้าม (ไม่บันทึกซ้ำ)**
   - **ถ้าไม่ซ้ำ → บันทึกเข้าฐานข้อมูล**

2. **การนำเข้าทีละไฟล์**
   - แต่ละครั้งที่อัปโหลดจะสร้าง Report แยกกัน
   - เช่น:
     - Report 1: "รายงานสั่งผลิต_5_มิ.ย._2569" (5 PO)
     - Report 2: "รายงานสั่งผลิต_10_มิ.ย._2569" (7 PO)
     - Report 3: "รายงานสั่งผลิต_25_มิ.ย._2569" (2 PO)

3. **ในหน้า Monthly Cost**
   - ระบบจะรวม PO จาก **ทุก Report**
   - กรองตามวันที่เป้าหมายส่งมอบ
   - แสดง PO ทั้งหมดที่ครบกำหนดในเดือนนั้น (ไม่ซ้ำกัน)

**สรุป:** ระบบรองรับการอัปโหลดหลายครั้งในเดือนเดียวกัน และจะไม่บันทึก PO ซ้ำ

### 6. ค้นหาราคาสินค้าอ้างอิง (Product Search)
**หน้า:** `/ProductSearch/Index` (ใช้ได้ทั้ง Admin และ Staff)

#### ขั้นตอน:
1. **พิมพ์คำค้นหา** (รหัสสินค้า หรือ ชื่อสินค้า)
2. **ระบบค้นหาจากตาราง `ProductPrice`**
   - ค้นจาก `ProductCode` และ `ProductName`
   - แสดงผลลัพธ์:
     - รหัสสินค้า
     - ชื่อสินค้า
     - หน่วย
     - ราคาต่อหน่วย
     - แหล่งข้อมูล (บิลไหนบ้างที่มีสินค้านี้)

#### ข้อมูลราคาอ้างอิงมาจากไหน?
- อ่านจากไฟล์ JSON: `wwwroot/data/price_per_unit.json`
- นำเข้าครั้งแรกตอน Startup (ถ้าตารางว่าง)
- ข้อมูลรวบรวมจากหลายบิลเพื่อหาราคาเฉลี่ย

## Flow แบบสรุป (ภาพรวมทั้งหมด)

```
1. อัปโหลดไฟล์สั่งผลิต (FileImport)
   ↓
2. ระบบอ่านข้อมูล และแสดงตัวอย่าง
   ↓
3. เลือก Columns และบันทึกเป็น Report
   ↓
4. บันทึก PO ลงตาราง OrderTrackingMaster (เช็คไม่ให้ซ้ำ)
   ↓
5. อัปโหลดไฟล์แผนผลิตรายสัปดาห์ (FileMerge)
   ↓
6. ระบบจับคู่ PO กับแผนผลิต
   ↓
7. บันทึก WeeklyPlan และ WeeklyPlanDetail (พร้อมวันที่ส่งมอบ)
   ↓
8. ดูรายงาน (Report/Index, Report/Details)
   ↓
9. คำนวณค่าใช้จ่ายประจำเดือน (MonthlyCost)
   ↓
10. เลือกสถานะการรับมอบ (Received/Deferred/Skipped)
    ↓
11. บันทึก MonthlyOrderAction
    ↓
12. แสดงสรุปค่าใช้จ่ายเดือน
```

## ตัวอย่างการใช้งานจริง

### สถานการณ์: สั่งผลิตชิ้นส่วนเดือนมิถุนายน 2569

#### Step 1: นำเข้าไฟล์สั่งผลิต
- อัปโหลดไฟล์ Excel ที่มี PO: WO26060219, WO26060214, WO26060213 (31 รายการ)
- ระบบสร้าง Report ชื่อ "รายงานสั่งผลิต_13_มิ.ย._2569"
- บันทึก 31 PO ลง `OrderTrackingMaster`

#### Step 2: อัปโหลดแผนผลิตสัปดาห์ที่ 1
- ผู้ผลิตส่งแผนมาวันที่ 18 มิ.ย.
- มี PO: 26062506, 26062425, 26062424, 26062009, 26062422
- ระบบจับคู่กับ WO26060219 → 26062506 ✅
- บันทึกวันที่เป้าหมายส่งมอบ: 20/07/2569

#### Step 3: อัปโหลดแผนผลิตสัปดาห์ที่ 2
- ผู้ผลิตส่งแผนเพิ่มวันที่ 25 มิ.ย.
- มี PO: 26062008, 26062007, 26062006, 26062005
- ระบบจับคู่กับ WO26060167 → 26062008 ✅
- บันทึกวันที่เป้าหมายส่งมอบ: 01/08/2569

#### Step 4: ดูรายงาน
- เข้า `/Report/Index`
- เลือกดู "รายงานสั่งผลิต_13_มิ.ย._2569"
- เห็นว่า 25/31 PO จับคู่สำเร็จ (80% Match Rate)

#### Step 5: คำนวณค่าใช้จ่ายเดือน กรกฎาคม 2569
- เข้า `/MonthlyCost/Index`
- เลือกดู "กรกฎาคม 2569"
- เห็น PO ที่ครบกำหนดส่งมอบ:
  - WO26060219 (1,026.52 บาท) - เป้าหมาย 20/7/69
  - WO26060214 (2,765.73 บาท) - เป้าหมาย 20/7/69
  - ... (รวม 15 รายการ)

#### Step 6: เลือกสถานะการรับมอบ
- WO26060219 → ✅ รับแล้ว (นับเข้าค่าใช้จ่าย)
- WO26060214 → ⏭️ ผ่อนไปเดือนถัดไป
- WO26060213 → ❌ ข้าม (ยกเลิก)

#### Step 7: บันทึกและสรุป
- บันทึก Actions ลง `MonthlyOrderAction`
- สรุปค่าใช้จ่ายเดือน กรกฎาคม 2569 = 45,320.50 บาท

## คำอธิบายเพิ่มเติม

### ทำไมต้องแยก Report กับ WeeklyPlan?
- **Report** = ไฟล์สั่งผลิตหลัก (ข้อมูลที่เราสั่ง)
- **WeeklyPlan** = แผนผลิตที่ผู้ผลิตแจ้งกลับมา (อาจจะแบ่งหลายรอบ/สัปดาห์)
- **เหตุผล:** เราสั่ง 1 ครั้ง แต่ผู้ผลิตอาจส่งแผนมาหลายครั้ง (แบ่งตามสัปดาห์/ความพร้อม)

### ทำไมต้องมี MonthlyOrderAction?
- เพื่อบันทึก**การตัดสินใจจริง**ของแต่ละเดือน
- ตัวอย่าง:
  - PO เป้าหมาย กรกฎาคม แต่ของมาล่าช้า → ผ่อนไปสิงหาคม
  - สิงหาคมต้องจ่ายค่า PO นี้ (IsForcedPayment = true)

### ทำไมต้องเช็ค PO ซ้ำ?
- ป้องกันการนำเข้าข้อมูลซ้ำ
- ตัวอย่าง:
  - วันที่ 5: อัปโหลด WO26060219 แล้ว
  - วันที่ 10: อัปโหลดอีกครั้ง ถ้ามี WO26060219 → ไม่บันทึกซ้ำ

### ข้อจำกัดปัจจุบัน
1. ระบบยังไม่รองรับการแก้ไข PO หลังบันทึก
2. การลบ Report จะลบ PO ที่เกี่ยวข้องทั้งหมด (Cascade Delete)
3. ราคาอ้างอิงต้องนำเข้าด้วย JSON (ยังไม่มีหน้าแก้ไขในระบบ)

## เทคโนโลยีที่ใช้

### Backend
- **ASP.NET Core MVC** - Framework หลัก
- **Entity Framework Core** - ORM สำหรับจัดการฐานข้อมูล
- **MySQL** - ฐานข้อมูล
- **ASP.NET Core Identity** - จัดการผู้ใช้และสิทธิ์

### Frontend
- **Razor Views** - Template Engine
- **Bootstrap** - UI Framework
- **JavaScript/jQuery** - Interactivity
- **Tailwind CSS** - Utility-first CSS

### Libraries
- **ClosedXML** - อ่าน/เขียนไฟล์ Excel (.xlsx)
- **CsvHelper** - อ่านไฟล์ CSV
